# اپلیکیشن ارزیابی کیفیت عملکرد کارشناسان CRM

اپلیکیشن دسکتاپ ویندوزی برای تحلیل و مقایسه کیفیت ثبت اطلاعات در CRM و
عملکرد کارشناسان خدمات پس از فروش بین دو بازه زمانی، بر پایه دو فایل
Export شده از Dynamics CRM (Notes و Tasks).

> **نسخه فعلی، MVP کامل و واقعی است** (نه Mockup): تمام مسیر Upload →
> اعتبارسنجی → Rule Engine → AI اختیاری → مقایسه دو دوره → رتبه‌بندی →
> Dashboard → Export روی داده‌های واقعی شما تست شده است. بخش‌های که در
> این نسخه پیاده‌سازی نشده، صریحاً در بخش «محدودیت‌های شناخته‌شده» در
> پایین همین فایل آمده‌اند.

---

## ۱. پیش‌نیازها

- ویندوز ۱۰ یا ۱۱
- Python نسخه ۳.۱۰ یا بالاتر ([python.org](https://www.python.org/downloads/) — هنگام نصب تیک «Add python.exe to PATH» را بزنید)
- WebView2 Runtime (روی اغلب سیستم‌های ویندوز ۱۰/۱۱ از قبل نصب است؛ در صورت نیاز، ویندوز خودش هنگام اجرای اول آن را نصب می‌کند)

## ۲. نصب و اجرا

ساده‌ترین روش: روی فایل **`run.cmd`** دابل‌کلیک کنید. این اسکریپت:
1. در صورت نیاز، درخواست دسترسی Administrator می‌دهد (به بخش «نکته
   مهم» زیر مراجعه کنید) و یک پنجره UAC نشان می‌دهد — «Yes» را بزنید.
2. پکیج‌های `requirements.txt` (فقط `openpyxl` و `pywebview`) را نصب می‌کند.
3. برنامه را اجرا می‌کند.

اجرای دستی (در Command Prompt، به‌عنوان Administrator):
```
pip install -r requirements.txt
python main.py
```

### نکته مهم: چرا Administrator لازم است؟

روی برخی سیستم‌های ویندوزی، حتی کاربری که عضو گروه Administrator است،
به‌طور پیش‌فرض با یک دسترسی محدودشده («Filtered Token») اجرا می‌شود مگر
برنامه صریحاً درخواست Elevation کند. یک باگ شناخته‌شده در تعامل بین
pywebview/WebView2 و ابزارهای Accessibility ویندوز (UI Automation) باعث
می‌شود بدون این دسترسی، برنامه هنگام راه‌اندازی **Hang** کند (پنجره باز
نمی‌شود یا کاملاً یخ می‌زند). `run.cmd` از این نگارش به بعد خودش
به‌صورت خودکار درخواست Elevation می‌دهد؛ اگر با این حال باز هم مشکل
داشتید، دستی روی `run.cmd` راست‌کلیک کرده و «Run as administrator» را
بزنید.

## ۳. جریان کار در اپلیکیشن

1. **بارگذاری فایل‌ها**: فایل Notes و Tasks را انتخاب کنید. برنامه ستون‌ها را
   خودکار شناسایی می‌کند و خلاصه اعتبارسنجی (تعداد رکورد، Case یکتا، رکورد
   ناقص، هشدارهای Mapping) را نشان می‌دهد.
2. **گروه‌بندی کارشناسان (اختیاری ولی توصیه‌شده)**: از منوی «گروه‌بندی
   کارشناسان»:
   - می‌توانید دکمه «بررسی و ایجاد گروه‌های پیش‌فرض» را بزنید تا دو گروه
     «Help Desk» (ارزیابی بر اساس **Case**) و «پشتیبانی فنی» (ارزیابی بر
     اساس **Task**) با تطبیق تقریبی نام‌های داده‌شده روی نام کامل
     کارشناسان واقعی پیشنهاد شود؛ قبل از ذخیره نهایی، نتیجه تطبیق (قطعی /
     چندگانه / پیدانشده) نمایش داده می‌شود تا تأیید کنید.
   - یا با جستجوی نام، گروه دلخواه خودتان را بسازید و مشخص کنید ارزیابی
     آن گروه بر اساس Case باشد یا Task.
   - گروه‌های ذخیره‌شده، بعداً هم از همین صفحه قابل ویرایش (افزودن/حذف
     عضو) هستند.
3. **بازه‌های زمانی و اجرا**: دو **تاریخ** (بدون ساعت) با انتخاب‌گر
   **شمسی** مشخص کنید (پیش‌فرض: دو نیمه مساوی از کل بازه داده). در صورت
   نیاز، یک گروه کارشناسان خاص را انتخاب کنید — واحد بررسی (Case یا Task)
   خودکار از تنظیمات همان گروه گرفته می‌شود؛ در غیر این صورت «همه
   کارشناسان» بر اساس Case تحلیل می‌شوند. سپس «اجرای تحلیل» را بزنید.
4. **معیارها و وزن‌ها** / **تنظیمات AI**: قبل یا بعد از اجرا قابل تغییرند؛
   برای اعمال تغییرات، تحلیل را دوباره اجرا کنید (یک یادآوری همین موضوع
   بالای صفحه معیارها نمایش داده می‌شود).
5. گزارش‌ها (Dashboard، مقایسه، رتبه‌بندی، تحلیل Case/Task، Caseهای
   نیازمند بررسی، سلامت داده، جمع‌بندی مدیریتی) بعد از اجرای تحلیل
   به‌روزرسانی می‌شوند. روی هر ردیف کارشناس یا Case/Task کلیک کنید تا یک
   پنجره (Modal) با جزئیات/Timeline و **گزارش بازخورد** (نقاط قوت/ضعف
   مستند با Evidence واقعی + برنامه بهبود پیشنهادی) باز شود — این پنجره
   از هر صفحه‌ای (تحلیل Caseها، Caseهای نیازمند بررسی، جزئیات کارشناس)
   یکسان کار می‌کند. در صفحه «تحلیل Caseها» می‌توانید بر اساس کارشناس یا
   Status Reason هم فیلتر بزنید.
6. **Export**: خروجی کامل اکسل (۸ شیت) یا CSV یک جدول مشخص برای گزارش
   تحلیل؛ همچنین از صفحه «معیارها»، کل تنظیمات برنامه (معیارها، گروه‌ها،
   تنظیمات AI بدون کلید) با Export/Import بین سیستم‌ها قابل انتقال است.
7. **گزارش اختصاصی هر کارشناس**: در پنل جزئیات کارشناس (صفحه
   «رتبه‌بندی»)، دکمه «Export گزارش این کارشناس» یک فایل اکسل مستقل
   می‌سازد که شامل خلاصه عملکرد، مقایسه با میانگین تیم، کارنامه کامل
   معیارها، نقاط قوت/ضعف اولویت‌بندی‌شده با نمونه واقعی، Feedback آماده
   ارائه، برنامه بهبود، و جمع‌بندی مدیریتی است — آماده ارسال مستقیم به
   همان کارشناس یا استفاده در جلسه Feedback.

### گزارش بازخورد کارشناس (Feedback)

در پنل جزئیات هر کارشناس (صفحه رتبه‌بندی)، سیستم به‌صورت خودکار:
- معیارهایی که میانگین امتیازشان برای آن کارشناس زیر ۶۰ است را به‌عنوان
  **نقطه قابل بهبود** با تعداد Case واقعی پشتوانه و نمونه Evidence نشان
  می‌دهد؛
- معیارهایی با میانگین ۸۰ به بالا را به‌عنوان **نقطه قوت مستند** نشان
  می‌دهد؛
- جملات به سبک «واقعیت به‌جای قضاوت کلی» تولید می‌شوند (مثلاً «در ۵۱ Case،
  میانگین امتیاز X بوده» به‌جای «شما ضعیف هستید»)؛
- یک **برنامه بهبود** با اولویت‌بندی بر اساس ضعیف‌ترین معیارها ساخته
  می‌شود.

این بخش کاملاً Rule-Based است (نه AI) — همه اعداد از امتیازهای واقعی
محاسبه‌شده می‌آیند، نه حدس مدل زبانی.

### تفاوت ارزیابی Case-based و Task-based

برای گروه‌های Help Desk، واحد ارزیابی «Case» است (هر Case از Noteها و
Taskهایش تشکیل می‌شود و امتیاز می‌گیرد). برای گروه‌های پشتیبانی فنی، واحد
ارزیابی «Task» است: هر Task مستقیماً بر اساس صاحبِ ثبت‌کننده‌اش
(`Created By`) و با ۴ معیار مستقل Task (کیفیت شرح، ثبت نتیجه، رعایت Due
Date، مدیریت Follow-up) ارزیابی می‌شود — نه در بستر کل Case. این دو مسیر
کاملاً مستقل هستند و می‌توان در آینده واحد بررسی سوم (مثلاً تماس تلفنی)
هم اضافه کرد بدون تغییر در دو مسیر موجود.

## ۴. ساختار پروژه

```
app/
  main.py                  نقطه ورود (پنجره pywebview)
  bridge.py                لایه API پایتون↔جاوااسکریپت
  pipeline.py               هماهنگ‌کننده Load→Score→Compare
  data/        loader / mapper / validator / cleaner (Mapping ستون‌ها و اتصال Task↔Case)
  analysis/    rules / scoring / experts / comparison / suspicious / data_quality / timeline
  ai/          providers / prompts / schemas / analyzer  (لایه AI، کاملاً اختیاری)
  config/      default_criteria.json + criteria_config.py (معیارها، وزن‌ها، قابل توسعه)
  database/    db.py (SQLite برای تنظیمات/Cache + ذخیره امن کلید API با Windows DPAPI)
  reports/     excel_export.py / csv_export.py
  ui/          index.html / styles.css / app.js  (بدون فریم‌ورک، آفلاین کامل — Chart.js و فونت Vazirmatn داخل پروژه هستند)
  tests/       تست‌های واحد (pytest)
```

افزودن معیار Rule جدید = یک تابع در `analysis/rules.py` + یک ورودی در
`config/default_criteria.json`؛ تغییر وزن/فعال‌بودن معیارهای موجود یا
نسبت Objective/AI هیچ تغییر کدی نمی‌خواهد (از داخل خود اپ قابل انجام است).

## ۵. یافته‌های واقعی از داده‌ی نمونه شما (برای اطمینان از صحت پردازش)

با دو فایل نمونه‌ای که فرستادید:
- ۱۷٬۱۴۰ Note، ۱٬۲۶۸ Task، ۵٬۴۶۷ Case یکتا شناسایی شد؛ بارگذاری کامل حدود ۸ ثانیه طول کشید.
- چون فایل Task شماره Case نداشت، ۹۰۹ Task با اطمینان «متوسط» (تطبیق متنی
  دقیق Regarding با عنوان Case) و ۲۱۴ Task با اطمینان «پایین» (چند Case
  هم‌عنوان، انتخاب بر اساس نزدیک‌ترین زمان) و ۱۴۵ Task بدون هیچ تطبیقی متصل
  شدند. **به‌محض این‌که شماره Case را در Export فایل Task اضافه کنید،
  اتصال به‌طور خودکار به حالت «قطعی» ارتقا پیدا می‌کند** — نیازی به تغییر
  کد نیست.
- شاخص سلامت داده CRM (مستقل از عملکرد کارشناسان) در حدود ۸۵ تا ۸۶ از
  ۱۰۰ محاسبه شد؛ ضعیف‌ترین مورد «Case بدون Task» بود (چون اغلب Caseها فقط
  با Note مدیریت می‌شوند، نه Task).
- یک یافته قابل‌توجه: در بخش بزرگی از Caseهای با وضعیت Resolved، متن
  Noteها به‌صراحت «نتیجه/رفع شد» را ذکر نمی‌کند (even though عملیات واقعاً
  انجام شده) — همین موضوع دقیقاً یکی از نقاط ضعف مستندسازی است که این
  اپلیکیشن قرار است نشان بدهد.

## ۶. محدودیت‌های شناخته‌شده در این نسخه (صریح و با دلیل فنی)

- **کلیک روی کارشناس در صفحه «تحلیل کلی»** پنل جزئیات را فقط اگر یک
  تحلیل «مقایسه دوره‌ها» هم قبلاً اجرا شده باشد نشان می‌دهد (چون پنل
  جزئیات فعلی برای مقایسه دو دوره طراحی شده)؛ در غیر این صورت بی‌صدا
  کاری نمی‌کند (نه خطا می‌دهد، نه کرش می‌کند). گزارش اختصاصی مستقل برای
  حالت تحلیل کلی در فاز بعد قابل افزودن است.
- **معیارهای `task_presence_when_needed` و `task_case_relation`** طبق
  تصمیم فاز صفر ممیزی، غیرفعال شدند (چون داده قابل‌اعتمادی برای تشخیص
  نیاز واقعی به Task یا نبود در دسترس نیست). این یعنی الان یک وزن کوچک
  از ظرفیت معیارها خالی می‌ماند؛ اگر بخواهید می‌توانید وزن معیارهای دیگر
  را در تنظیمات افزایش دهید یا منتظر فاز ۲ (بازطراحی کامل سه‌لایه)
  بمانید که این‌ها را به شکل درست‌تری در «سلامت داده» بازتعریف می‌کند.
- **بازطراحی کامل سه‌لایه (Agent Performance / Case Outcome / Case
  Intelligence)** که در فاز ۰ و ۱ توافق شد، هنوز پیاده‌سازی نشده. آنچه
  در این نگارش انجام شد (اجرای مجدد، تحلیل کلی، Navigation، فیلترها،
  N/A شدن دو معیار) پیش‌نیاز و بخشی از همان مسیر بود، اما Coverage/
  Confidence صریح، جداسازی کامل Case Outcome، و Config-پذیر شدن
  آستانه‌های زمانی هنوز در انتظار تأیید برای فاز ۲ است.

- **معیار Scenario به‌صورت Rule-Based ساده است** (بررسی وجود/طول/همپوشانی
  با کلیدواژه‌های مشکل)، نه تحلیل معنایی عمیق؛ برای ارزیابی کیفی‌تر
  محتوای Scenario می‌توان آن را در آینده به یک معیار HYBRID (با AI) تبدیل
  کرد.

- **گزارش اختصاصی کارشناس فعلاً فقط اکسل است، نه PDF.** طبق تصمیم مشترک،
  فرمت اکسل برای این نسخه انتخاب شد چون زیرساختش آماده بود و سریع‌تر
  می‌رسید؛ PDF (که ظاهر رسمی‌تری برای ارائه مستقیم دارد) نیاز به یک
  کتابخانه جدید (`reportlab` یا مشابه) دارد که هنوز اضافه نشده.
- **تفکیک Manager View / Employee View پیاده نشده** — فعلاً یک فایل واحد
  (همانی که مدیر می‌بیند) ساخته می‌شود. اگر بعداً نیاز شد نسخه ساده‌تر و
  بدون مقایسه با تیم برای ارسال مستقیم به کارشناس، قابل افزودن است.

- **شناسه نمایشی Task**: چون فایل Task ستون «شماره Task» خوانا ندارد (فقط
  شناسه فنی GUID)، در جدول‌های حالت Task-based همان GUID به‌عنوان شناسه
  نمایش داده می‌شود؛ عنوان (Subject) معمولاً خواناتر است.
- **AI برای معیارهای Task مستقل فعلاً پیاده نشده** (همه ۴ معیار
  Task-based، Rule-Based هستند)؛ چون در این مرحله لایه AI درخواست نشد.
  ساختار برای افزودن بعدی آماده است.

- **Export PDF پیاده‌سازی نشده.** طبق توافق، دامنه نسخه اول روی Export
  اکسل متمرکز شد؛ PDF نیاز به یک پکیج سنگین‌تر (مثل `reportlab` یا
  `weasyprint`) دارد که فعلاً اضافه نشده. Export CSV به‌عنوان جایگزین سبک
  اضافه شده است.
- **دسته «کیفیت کارشناسی» کاملاً به AI وابسته است** (دقیقاً طبق درخواست
  پرامپت شما). اگر AI غیرفعال باشد، این معیارها به‌طور شفاف از محاسبه
  Final Score کنار گذاشته می‌شوند (نه اینکه امتیاز جعلی/صفر بگیرند).
- **Providerهای AI پیاده‌سازی‌شده**: OpenAI، هر API سازگار با OpenAI
  (شامل Local Model هایی مثل Ollama/LM Studio که سرور OpenAI-Compatible
  را فعال کرده باشند — از گزینه «Custom» و Base URL محلی استفاده کنید)، و
  Google Gemini. کلاینت اختصاصی برای هر مدل دیگری نوشته نشده؛ افزودن آن
  یک کلاس کوچک در `ai/providers.py` است.
- **مجموعه معیارها زیرمجموعه‌ای معرف از ۷۳+ معیار پرامپت اصلی است**
  (حدود ۴ تا ۶ معیار در هر دسته، نه هر ۱۷/۱۲/۹/۱۳/۱۰ مورد). این‌ها
  پرکاربردترین و قابل‌محاسبه‌ترین معیارها هستند؛ افزودن معیار جدید ساده
  است ولی نیاز به یک تابع Python کوچک دارد (نه فقط تنظیمات).
- **تشخیص موارد مشکوک Rule-Based است**, نه یادگیری ماشین؛ روی داده واقعی
  شما تعداد نسبتاً زیادی (حدود ۴٬۳۰۰ از ۵٬۴۶۷ Case) را به‌عنوان
  «نیازمند بررسی» علامت زد — عمدتاً به‌خاطر همان یافته بخش ۵ (نتیجه اقدام
  در متن ذکر نشده). صفحه UI این‌ها را با دلیل مشخص نشان می‌دهد تا قابل
  اولویت‌بندی باشد؛ فیلتر/دسته‌بندی پیشرفته‌تر روی این لیست در این نسخه
  اضافه نشده.
- **Mapping ستون‌ها خودکار است و از UI قابل ویرایش دستی نیست** (فقط در
  Upload به‌صورت هشدار نمایش داده می‌شود). اگر روزی نام ستون‌ها به‌شکل
  غیرمنتظره تغییر کرد و Mapping اشتباه شناسایی شد، یا باید ستون منبع را
  تغییر نام دهید یا این بخش را در فاز بعد اضافه کنیم.
- **عملکرد روی حجم ۵۰هزار Note / ۱۰هزار Task طبق الزام پرامپت به‌صورت
  زنده تست نشده** (محیط توسعه من به شبکه/فایل با آن حجم دسترسی نداشت)؛
  آزمایش با ۱۷٬۱۴۰ Note واقعی شما (بارگذاری ۸ ثانیه، Scoring حدود ۱ ثانیه)
  نشان می‌دهد معماری از نظر سرعت مشکلی ندارد، ولی توصیه می‌کنم یک اجرای
  آزمایشی با حجم واقعی بزرگ‌تر انجام دهید.
- کلید API با Windows DPAPI رمزنگاری می‌شود (فقط برای همان کاربر ویندوزی
  روی همان سیستم قابل بازگشایی است)، دقیقاً مشابه روش اپ نمونه قبلی شما.
- **سند جدید «ارزیابی عملکرد و توسعه کارشناسان» (۶ محور KPI، Penalty
  Engine، Employee/Manager View، PDF کارشناس، Branding) هنوز پیاده‌سازی
  نشده.** طبق دستور شما، فعلاً فقط قابلیت‌های زیر از آن سند اضافه شده‌اند
  (بدون تغییر معماری اصلی): گروه‌بندی کارشناسان + اجرای تحلیل روی یک گروه
  خاص، فیلتر Status Reason، تاریخ شمسی، و یک نسخه اول از «گزارش بازخورد
  کارشناس» (نقاط قوت/ضعف مستند + برنامه بهبود، Rule-Based). بقیه موارد آن
  سند (Penalty Engine، ۶ محور رسمی، PDF کارشناس، Case Detail Modal کامل،
  Branding با Logo واقعی، تفکیک Manager/Employee View) در گزارش بررسی
  جداگانه‌ای که فرستادم مطرح شدند و منتظر تصمیم شما درباره فازبندی و
  داده‌های موردنیاز (مثل سیاست SLA) هستند.
- **انتخاب‌گر تاریخ شمسی** با تقویم داخلی مرورگر (`Intl` با `calendar:
  persian`) ساخته شده که در WebView2 (Chromium) به‌صورت بومی و دقیق
  پشتیبانی می‌شود؛ روی ۳۴۰۰+ تاریخ آزمایشی (شامل مرز نوروز و سال‌های
  کبیسه) تست شد و خطایی نداشت.
